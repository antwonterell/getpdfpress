Keep the larger target when the form allows it

The 500KB tool target is 512,000 bytes. A decimal 500KB portal limit may instead mean 500,000 bytes. If your original is already within the receiving limit, keeping it can preserve text and detail without another processing step.

For our image-heavy sample, the 500KB output used 178,842 bytes versus 66,963 at 200KB. The larger result kept more visible fine-text detail, but neither retained selectable text. A resume or a document needed for search/copy may be better re-exported digitally than rasterized.

Rasterizing the two-page sample removed selectable text and changed page dimensions: the original was 612 x 792 points; the 200KB output is 465 x 602 and the 500KB output is 664 x 860. A matching page count does not prove that print size, accessibility, links or interactive features survived. We did not test forms, signatures, OCR, or ConvertAPI output.

Inspect the full-size readability comparison. Each first-page crop is rendered at an equal 816-pixel page width, not an equal physical print size. The original 6-point line is clear; the 200KB result is heavily blurred, while the 500KB result is clearer but softened. This is a visual judgment on this sample, not an automatic readability score.

Why exact targets vary

Page content, embedded fonts, images and existing compression all affect the result. Compression is best-effort. Open the result and check text, signatures, and images before using it.

Best for real upload limits

Read the receiving form first. Choose a target only when it fits the stated limit, and split documents only if separate uploads are allowed. Keep every required page.
