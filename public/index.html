How the compressor works

Compression tries available methods and compares output sizes. The result depends on the document.

1. Light optimization

The first attempt rewrites the PDF with a native library. It may reduce structural overhead, but this is not a metadata-sanitization or redaction tool.

2. Smart recompression

If the native attempt misses the target, configured ConvertAPI compression and image-based fallback methods may be tried. Image-based compression can soften text and affect selectable text; inspect the result.

3. Verify and retry

The server compares candidate sizes and keeps a smaller result when available. Some methods try several settings. If compression cannot make a smaller file, the original is returned. A smaller file still needs your readability check.
